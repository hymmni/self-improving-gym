# STG 예측기: 롤아웃 데이터 양에 따른 일반화 실험 설계

작성 2026-11-20. 데이터 수집과 검사는 끝났고, 실험 설계도 사용자와 하나씩 정했다(아래 "정한 것").
이 문서를 근거로 플랜을 쓰고 실행한다. 여기 없는 판단이 필요하면 사용자에게 묻는다.

## 왜 하나

STG 예측기 d(o)는 "지금 상태에서 성공까지 남은 스텝"의 분포를 예측하고, 그 기댓값을 RL 보상에 쓴다.
사람 시연만으로 학습하면 정책이 실제로 가는 상태(특히 실패로 가는 상태)를 본 적이 없다.
**정책 롤아웃(성공 롤아웃 + 사람 개입 에피소드)을 몇 개 모아야 예측기가 그 정책의 상태에서 제대로 맞히는가**를
데이터 양을 10개 단위로 늘려 가며 잰다.

## 질문

1. **주 질문:** 롤아웃 수 n = 0, 10, 20, …을 늘릴 때 처음 보는 에피소드에서 예측기 성능이 어떻게 변하고, 어디서 평탄해지는가.
2. **개입 시점:** 같은 버튼 시점에서 출발한 세 가지 개입 데이터 중 무엇이 가장 도움이 되는가.
   - 지연: 버튼(t_press) 뒤 무작위 지연 후 넘겨받음
   - 즉시: t_press에서 바로 넘겨받음
   - 타임아웃: 정책이 시간 제한까지 혼자 간 끝에서 넘겨받음
3. **성공 롤아웃:** 정책 혼자 성공한 에피소드를 학습에 넣을 때와 뺄 때 차이가 있는가.
4. **입력:** 고유수용 감각(lowdim), 손목 이미지, agentview 이미지 조합에 따라 어떻게 다른가.

정책은 random30과 turn30 두 개다. yawlim30은 논문에 쓸 수 없어서 뺀다(사용자 결정).

  - 타임아웃 개입: 정책이 시간 제한까지 간 뒤부터 intv다.
- **사람 구간 길이(개입 시작~성공)**, p90 / 최대:

- **화면 무결성:** 이 표의 파일은 모두 저장된 sim 상태로 다시 그려 프레임마다 확인했다(`scripts/audit_render.py`, 렌더 버그 프레임 0).

## 정한 것

### 데이터 사용 원칙 (이전 대화에서 사용자 결정)
- **모르는 라벨은 학습하지 않는다.** t_press~t0는 사람이 실패라고 본 뒤 정책이 계속 간 구간이라 정답이 없다. 0~t_press도 예전부터 학습에서 뺐다.
  - 학습하는 프레임: 데모 전체, 개입 에피소드의 intv 구간, (넣는 조건에서는) 정책 단독 성공 에피소드 전체.
  - 학습하지 않는 프레임: 개입 에피소드의 rollout과 preintv 구간.
- **야매 성공**은 학습과 평가 지표에서 빼고 개수만 보고한다. 실패로 라벨을 붙이지 않는다.
- **bin 수 = 그 정책 학습 데모의 최대 길이 × 2**이므로 random30은 522, turn30은 888이다.
  VIP 설정의 기본값 `num_bins_override: 256`을 반드시 덮어써야 한다.
- **반사실 분기는 한 번만 돌린다.** 예측기는 분포를 내므로 한 번짜리 결과도 여러 에피소드에 걸쳐 공정하게 채점된다.
- **지연 상한은 남은 시간 전체**(U{0..max_steps−t_press−1})다. 고정 상한을 두면 실패 상태 일부가 학습 밖(OOD)으로 남는다.
- **평가 세트**는 처음 보는 사람 데모와 같은 정책의 학습에 안 쓴 롤아웃이다.
- **분기 재현성 검증은 하지 않는다.** 목적은 정책이 아니라 예측기의 반응을 보는 것이다.

### 실험 설계 (2026-11-20, 사용자와 하나씩 정함)
1. **평가용으로 뺄 롤아웃:** 정책마다 개입 15개 + 정책 단독 성공 6개를 이름(`demo_k`)으로 고정해 뺀다.
   - 개입 15개는 세 조건 공통 에피소드에서 고른다. 수집 순서가 고르게 섞이게 뽑고, 목록 파일로 남긴다.
   - 모든 조건과 모든 n에서 같은 목록을 쓴다. 뺀 에피소드의 즉시·타임아웃·분기 버전도 학습에 쓰지 않는다.
2. **에피소드 짝 맞추기, 두 경우 모두 실험한다(어블레이션).**
   - (가) 같은 에피소드: 세 조건 모두 공통 에피소드만 쓴다.
   - (나) 있는 대로: 지연·즉시는 그 파일에 있는 에피소드를 다 쓴다. random30은 `demo_67`, turn30은 위 9개가 학습 풀에 더해진다.
   - 타임아웃은 두 경우가 같다.
3. **n = 정책을 돌린 원본 에피소드 수**(개입과 정책 단독 성공이 섞인 그대로).
   - 원본 이름의 순열 앞에서부터 n개를 고르고, 같은 순열 안에서 n이 커지면 앞의 것에 더한다.
   - 성공을 빼는 조건은 같은 n개 중 정책 단독 성공만 뺀다. 그래서 같은 n이면 개입 데이터가 같고, 세 개입 조건도 같은 원본 에피소드를 쓴다.
   - n = 0(데모만)은 모든 조건이 공유한다. n은 10 단위로 학습 풀 크기까지다(마지막은 풀 전체).
   - 학습 풀은 (가)에서 random30 68개(개입 52 + 성공 16), turn30 60개(개입 40 + 성공 20)다.
   - 학습 프레임 수를 x축으로 한 곡선도 보조로 그린다.
4. **학습 길이:** 모든 n에서 gradient step 수를 같게 한다. 값은 가장 큰 n에서 충분히 수렴하도록 플랜에서 정하고 근거를 남긴다.
5. **시드:** 부분집합 순서 5개 × 학습 시드 2개 = 조건·n마다 예측기 10개다. 95% 구간은 평가 에피소드 단위 부트스트랩으로 낸다.
6. **bin 범위를 넘는 라벨:** 마지막 bin으로 모은다. random30은 사람 구간이 522를 넘는 프레임이 지연 2.2%, 타임아웃 3.9%이고, turn30은 0%다.
7. **입력:**
   - 비교할 조합은 7개 전부다: 전부, 두 카메라, 고유수용만, agentview만, 손목만, 손목+고유수용, agentview+고유수용.
     뒤의 두 개는 `obs_parts`에 새로 추가해야 한다.
   - 주 곡선(질문 1~3)은 "전부" 입력으로 그린다.
   - 입력 비교는 "지연 개입 + 성공 포함 + 같은 에피소드" 한 조건에서 곡선 전체로 한다.
8. **주 지표 두 개를 고정한다.** 나머지는 보조로 보고한다(아래 "평가").
   - ① 학습에서 뺀 롤아웃의 성공 구간 MAE
   - ② 실패 분기의 "거짓 진전" 비율
9. **실행:** Eddy 서버(RTX 3090 24GB, 접속 정보는 `docs/private/ENVIRONMENT.md`)와 로컬(3080Ti)에서 나눠 돌린다.
   예측기는 약 2,200개다. 먼저 시험 실행으로 하나당 시간을 재서 사용자에게 알린 뒤 전체를 띄운다.
10. **곡선은 정책별로 따로** 그린다. bin과 시간 제한이 다르므로 예측기도 정책마다 따로 학습한다.
11. **인코더:** VIP 특징(고정) + 헤드(`train_dstg_vip.py`)다. 특징은 한 번만 뽑아 모든 예측기가 같이 쓴다.

## 평가

모든 예측기를 그 정책의 같은 평가 세트로 채점한다. 어떤 조건으로 학습했든 평가 세트는 같다.

| 세트 | 출처 | 정답 |
|---|---|---|
| 정책 성공 | 뺀 정책 단독 성공 6개 | 남은 스텝(정확) |
| 개입 성공 구간 | 뺀 개입 15개의 intv 구간, 지연·즉시·타임아웃 버전 모두 | 남은 스텝(사람 복구 시간이라 잡음이 큼) |
| 실패 분기 | 뺀 개입 15개의 분기 t0·t_press(정책이 혼자 시간 제한까지 간 경로) 중 실패한 것 | 실패 |
| 데모 | 평가용 사람 데모 20개 | 남은 스텝(정확) |

**주 지표**
- ① **성공 구간 MAE:** "정책 성공"과 "개입 성공 구간" 프레임에서 예측 기댓값과 실제 남은 스텝의 차이다. 세트별 값도 같이 낸다.
- ② **거짓 진전 비율:** 실패 분기 가운데 d(분기 시작) − d(분기 끝) > 0, 즉 예측기가 "성공에 가까워졌다"고 본 분기의 비율이다.
  RL 보상 해킹과 바로 이어지는 값이다. 세부 정의(시작·끝을 한 프레임으로 볼지, 짧은 구간 평균으로 볼지)는 플랜에서 정하고 근거를 남긴다.

**보조 지표**
- NLL.
- 실패 경로 상태와 성공 경로 상태를 구분하는 AUROC. t_press는 사람이 위험하다고 본 시점이라, 이미 위험해 보이는 상태 안에서의 구분 능력이라는 점을 같이 적는다.
- 평가용 데모 MAE.
- `scripts/eval_dstg.py`의 보상 품질 지표: 스텝 차분의 부호 정확도, 에피소드 내 순위상관 등.

**"충분하다"의 기준:** 시드 편차와 부트스트랩 구간 안에서 곡선이 평탄해지는 n이다.

## 이미 있는 코드

- **`scripts/train_dstg_vip.py`**: VIP 특징 캐시 위에서 헤드를 학습한다.
  - `train_rollout_limit` + `split_seed`: 데모는 다 두고 롤아웃만 n개 남긴다. 같은 seed면 n이 커질 때 앞의 집합을 포함한다(`rollout_demos_to_drop`).
    다만 합친 파일의 이름으로 섞으므로, 원본 이름 기준 짝 맞추기(설계 3)는 새로 만들어야 한다.
  - `train_rollout_kind`: `all` / `no_intervention` / `intervention`.
  - `success_tail_only`: 데모와 무개입 성공은 전체를, 개입 성공은 마지막 개입 시작 이후만 학습한다. 위 "학습하는 프레임" 규칙과 같다. 동작을 테스트로 확인한다.
  - `train_modes`: `[demo, intv]`로 두면 성공 롤아웃(rollout 라벨)까지 빠진다.
  - `obs_parts`: 지금은 `all` / `feat` / `lowdim` / `agentview` / `wrist`.
  - `num_bins_override`, `record_curves`, `val_fraction`/`split_seed`(에피소드 단위 검증 분할). 이 실험에서는 평가 세트를 따로 고정하므로 학습 데이터에서 검증 분할을 떼지 않는다.
- **`scripts/cache_vip_feats.py`**: hdf5 → VIP 특징 캐시.
- **`scripts/merge_demo_hdf5.py`**: 여러 hdf5를 하나로 합친다.
  - 합친 에피소드 이름이 `demo_0..`으로 바뀌고 `attrs["source"]`에는 파일 경로만 남는다.
  - 원본 에피소드 이름은 남지 않는다.
- **`scripts/eval_dstg.py`**: 보상 품질 지표.

## 만들 것 (대략, 플랜에서 확정)

1. **평가용 목록 파일:** 설계 1에 따라 정책별로 고정한다.
2. **조건별 학습 데이터와 VIP 캐시:** 데모 30개 + 개입(지연 | 즉시 | 타임아웃) + 정책 단독 성공.
   - 원본 이름(`demo_k`)을 attrs에 남긴다.
   - 평가용 이름은 넣지 않는다.
   - 평가 세트도 캐시로 만든다.
3. **짝을 지키는 부분집합 선택:** 원본 이름 기준 순열(설계 3).
4. **`obs_parts` 두 조합 추가:** 손목+고유수용, agentview+고유수용.
5. **평가 스크립트:** 위 평가 세트별 지표, 부트스트랩 구간, 거짓 진전 비율을 낸다.
6. **실행 묶음:** Eddy와 로컬에 나눠 띄우고, 결과 표와 곡선 그림을 만든다.
   예측기가 많아 W&B는 끄고 폴더별 결과 파일로 남긴다. 2026-10-19 bin 비교 실험과 같은 이유이고, 띄울 때 사용자에게 알린다.

## 주의할 점 (예전 결과에서)

- **비슷해 보이는 상태:** 성공 라벨만 있으면 손목 이미지의 정보(너트를 제대로 잡았는지)를 무시해도 손실이 작다.
  실패로 가는 상태는 여전히 직접 감독을 받지 않으므로, 실패 분기에서 낙관적으로 예측하는 경향(거짓 진전)은 데이터를 늘려도 안 사라질 수 있다.
  이 가설을 결과 전에 실험 기록에 적어 둔다.
- **고유수용 지름길:** 고유수용 감각을 넣으면 팔 위치만으로 맞히는 지름길이 생길 수 있다. 입력 비교에서 이걸 확인한다.
- **개입 라벨 잡음:** 사람 복구 시간의 편차가 크다(위 사람 구간 표). 개입 데이터가 늘수록 곡선이 단조롭지 않을 수 있으므로 세트별 오차를 따로 본다.
- **오프라인 지표 ≠ RL에서의 안전:** 예전 DPPO에서 STG 보상이 해킹당했다. 오프라인 지표가 좋아도 RL에서 해킹당하지 않는다는 보장은 없으므로, 이 실험의 지표로 보상 유용성을 주장하지 않는다.
- **bin 설계:** 2026-10-19 비교에서 bin 재설계는 해킹을 못 막았고, σ∝T HL-Gauss는 보정만 나아졌다. 이 실험에서는 기본(index bin, one-hot)을 쓴다.
